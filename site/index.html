Škoda Mate

Self-hosted trip tracking and charge logging for Škoda cars, with charging and climate control.

Built on Škoda's official public API with an API key from the MyŠkoda app — no Škoda account password involved. Trips and charges are derived by Mate itself and kept in a local SQLite database. Docker image, one command, no cloud.

Features

Every dashboard page, in one glance. Everything runs on your own machine — the only external calls go to Škoda's API and, for maps, OpenStreetMap.

Overview

Car render, battery, range, charging state, doors/windows/lock, climate, position, last trip and charge, 48 h chart

Trips

Derived trips with day and month views, search, map, notes, cost, CSV export — plus duplicate-safe import of the MyŠkoda app's trip CSV

Charges

Sessions with energy, AC/DC, Home/Public, charging curve and cost, with CSV export

Prices

Your kWh prices for home, public AC and public DC. Costs recalculate everywhere; a charge's real total overrides the estimate

Battery

SoC history, charging settings and profiles, a capacity estimate built from your charges, and projected range at 100 %

Control

Charging on/off, charge limit and mode, charging profiles, climate, auxiliary heater and ventilation — only what this car supports, with a reason when it doesn't

Statistics

Monthly distance, energy, cost and consumption. Charging and Driving tabs with power, charge curves, destinations and heatmaps; a Parked tab for the battery lost while parked

Map & Places

Where the car stood and charged, plus named places with radius, colour and per-place prices — visits, days, parked time and cost per place

Activity

A day timeline of drive, charge, climate and parked time, and an event list with every command you sent

Data quality

A card that flags open trips, unseen charge ends and near-duplicates, offers safe fixes with undo, and never shows a guess as a number

Home Assistant

MQTT discovery with about 40 entities per car: sensors, tracker, buttons and a charge-limit slider (opt-in). Set up in the dashboard, no restart.

Signed webhooks for trips, charges, places and battery events, a JSON API with a bearer token, CSV export and database backup

What the API can — and cannot — do

Škoda's public API returns one live reading per request and a short command list. It has no history, which shapes everything Mate does: history is derived by Mate and clearly labelled where it is an estimate. Nothing is ever shown as a number when it is a guess.

✓Straight from the API

Live values and supported commands

  • Battery level, range, charging state and power
  • Doors, windows and lock status
  • Parking position and odometer
  • Start/stop charging, charge limit and mode
  • Climate, auxiliary heater (S-PIN) and ventilation
  • The car's official render

≈Derived by Mate, labelled honestly

No history in the API — Mate builds it

  • Trips, from odometer and the parked/driving state
  • Charges: measured when seen live, inferred and marked ≈ otherwise
  • Parked loss, capacity estimate, projected range
  • Costs, from your own prices
  • Statistics, places and visit history
  • A data-quality card with safe fixes

✗Not possible

The API offers nothing for it — so Mate doesn't pretend

  • Lock/unlock, honk or flash
  • Wake-up
  • A route line while driving (no position is reported)
  • Outside temperature, service and warning lights
  • Battery health (an estimate is shown instead)
  • Sending a destination to the car

Request budget: Škoda allows about 20 requests per hour per car. Mate polls every 20 minutes while parked and every 5 minutes while charging, climatising or driving, keeps 4 requests reserved for commands, and shows a live counter in the top bar — so you always know what the quota is doing.

Setup

Docker is the recommended way; three steps and you are looking at your car

1

Start the container

No image build, nothing to configure first: the image is published on Docker Hub as steffenr/skoda-mate for linux/amd64 and linux/arm64

mkdir -p ~/skoda-mate && cd ~/skoda-mate curl -LO https://raw.githubusercontent.com/steffenr/skoda-mate/main/docker-compose.yml docker compose up -d
2

Create an API key in the MyŠkoda app

Open go.skoda.eu/api-keys, create a key and select all your cars. Paste the key and your VIN(s) in the next step. No Škoda password is ever entered here; the 4-digit S-PIN is optional and only needed to start the auxiliary heater.

3

Open the dashboard and finish setup

Go to http://localhost:8080, create your dashboard login and paste the API key. Mate tests it against Škoda and stores it encrypted.

Port is yours to change: edit ports in docker-compose.yml. Updates are docker compose pull && docker compose up -d; your ./data folder survives.

Other ways in: on Unraid the app installs from Community Applications (search skoda-mate), or from the template and compose file in the repo. Any other NAS that runs Docker — Synology, Ugreen, QNAP and others — can use the same docker-compose.yml or the image from Docker Hub. DEMO=1 starts a fictional Enyaq with 60 days of history if you want to look around first; and before a login exists, the setup form asks for a one-time code from the log when reached from a public address
